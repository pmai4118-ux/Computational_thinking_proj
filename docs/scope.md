# P01 MVP scope: Backend Intern/Fresher interview practice

Status: revised by the user on 10 November 2026 to text-only technical practice.
Coding tasks, live-coding, LeetCode handoff, code storage/review and vibe coding /
AI-code critique are excluded. Text-answer rubric evaluation remains in scope.
The previous scope baseline was selected on 9 November 2026. It follows

## Audience and format

- Audience: Software Engineering students preparing for Backend Intern/Fresher
  technical interviews.
- Language: Vietnamese interface and question content; original source text is
  retained separately when material is translated or adapted.
- Session: four text-answer questions, one from each fixed MVP category:
  programming knowledge, technical case, algorithm explanation in prose, and
  technical reasoning/trade-offs. The fourth category replaces AI-code critique
  while retaining the existing four-question session length. C01 still owns the
  detailed skill catalog. No category requires writing, running or reviewing code.
  The first release uses fixed coverage; adaptive probing is deferred.
- Feedback: criterion-level rubric outcome, score when evidence supports one,
  explanation, and evidence linked to the exact saved answer. Unresolved evidence
  remains distinct from a zero score or a processing failure.

## Student outcome and MVP boundary

A student starts a practice session, answers the four questions, receives
evidence-linked rubric feedback, reviews the session's observed gaps, and opens a
reviewed exercise related to a gap. A failed evaluation preserves the saved answer
so the student can retry. Session history stays within the same anonymous browser
session. Results describe performance on the selected questions; the app does not
predict hiring outcomes or diagnose overall ability from one answer.

Include the browser application and Python backend, local demonstration with
synthetic profiles, fixture-based evaluation for development, answer persistence,
failure/retry handling, a session summary, and reviewed exercise recommendations.
Gemini remains the provisional live provider in the delivery plan; account access,
model choice, quota, and budget must be checked before live or paid use.

Content target from the delivery plan: at least eight reviewed questions, with
twelve as a target and at least two variants per category. These are planning
targets to validate against team capacity, not permission to import unreviewed
content.

## Content and review policy

Select questions and reusable materials from open-source sources whose license
covers the specific item. Preserve the original content, source URL, revision,
author, license, and required attribution. Record translation/adaptation changes.
The team writes and reviews the rubric. A reviewer other than the curator checks
source and license, technical correctness, observable rubric boundaries, and
equivalent valid answers before content is approved. Team members and reviewers
remain unassigned until the user allocates them.

## Deferred from the first release

Excluded by the latest user decision (not scheduled for a later release): coding
questions, code editors/submissions/storage, sandbox execution, LeetCode links or
submission tracking, AI-generated code critique and vibe-coding practice.

- Job-description analysis, broad job-market collection, and multiple career
  tracks.
- Study schedules, multi-session skill trends, and a complete course recommender.
- Adaptive question selection and Decision Replay.
- Voice input, screen monitoring, arbitrary code execution, and automatic
  question generation.
- Hosted deployment unless the class requirements make it necessary.
