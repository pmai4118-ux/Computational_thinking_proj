# Integration: Q01 + E05 + E06 + E09 + E04

Branch: `Merge-Q01-E05-E06-E09-E04`.

## What was combined

The branch starts from E09. Q01 was merged first; Q01 already contains the latest E05 evidence validation and E06 rubric scoring. E04 was then merged into this branch. The E09 evaluation service remains the one scoring and persisting saved answers; the E04 CLI now calls that same service. The E09 scorer still requires explicit satisfied-evidence indexes for a decidable score. The provider factory is shared by the web app and CLI.

The E04 CLI keeps its standalone JSON input/report format. The web app adds an owned saved-answer evaluation API and a minimal answer form/result page. Neither a GET request nor a repeated POST invokes the AI again after a completed result is cached.

## End-to-end paths

Web: open a session -> submit the original answer -> POST evaluation -> provider interprets each rubric criterion -> validate criterion IDs and exact quotes -> Python scores the declared rubric levels (`null` for unresolved evidence) -> build feedback -> save the result in SQLite -> GET the saved result and feedback. The browser form at `/sessions/{session_id}` submits and evaluates, then opens the result page. If the provider fails, the answer remains saved and the page offers a retry.

CLI: load the question/rubric/answer JSON -> run the same validation, scoring, and feedback service -> print a short summary -> write a JSON report. This standalone path does not save to the web application's SQLite database.

The API endpoints are:

- `POST /api/sessions/{session_id}` opens a session.
- `POST /api/sessions/{session_id}/answers` saves the verbatim answer.
- `POST /api/sessions/{session_id}/answers/{answer_id}/evaluate` evaluates saved revision `answer_revision` (default 1).
- `GET /api/sessions/{session_id}/answers/{answer_id}/evaluations/{revision}` reads an existing result without calling AI.

All evaluation/read requests verify the session owner cookie and that the answer belongs to that session. The response contains scores, evidence, feedback, model and prompt metadata, and the original answer.

## Reproduce locally (PowerShell, from the repository root)

Install the locked Python 3.11 dependencies using the repository README, then run:

```powershell
uv sync --locked
uv run --locked python -m pytest -q
uv run --locked python -m source.main --provider fixture --input test/fixtures/e04/inventory_answer.json --output .local/merge-report.json
$env:EVALUATION_PROVIDER = "fixture"
uv run --locked uvicorn source.main:create_app --factory --host 127.0.0.1 --port 8000
```

Open `http://127.0.0.1:8000/`, create a session, submit an answer, and inspect its result page. Fixture mode is an offline **demo**, not an AI-quality check.

For a live Antigravity session, install/sign in to `agy` as documented in `docs/E04-INSTRUCTION.md`. In a fresh PowerShell session, set:

```powershell
$env:EVALUATION_PROVIDER = "antigravity"
$env:ANTIGRAVITY_EXECUTABLE = Join-Path $env:LOCALAPPDATA "agyingy.exe"
uv run --locked uvicorn source.main:create_app --factory --host 127.0.0.1 --port 8000
```

The default Antigravity model in this branch is `gemini-3.8-flash-medium`; its availability depends on the signed-in account. Gemini API mode requires that user's own `GEMINI_API_KEY` and `GEMINI_MODEL` environment variables. It is also available through the CLI with `--provider gemini`. No key is committed.
